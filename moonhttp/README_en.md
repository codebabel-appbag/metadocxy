# User Manual: moonhttp (`moonhttp-v1.0.6`)

**moonhttp** (also known as `moonhttp`) is a lightweight, fast, and visually-oriented local HTTP server developed in Lua. It is designed to run as a standalone, cross-platform binary executable (supporting Linux, Windows, and macOS).

Its primary goal is to accelerate the local development of static web pages by offering a rich command-line interface (CLI) experience and immediate feedback on project file integrity.

---

## 1. Modules and Technologies Used

To build and package the standalone binary, only essential libraries from the Lua ecosystem were used:

* **LuaJIT / Lua 5.1**
* **LuaSocket**
* **LuaFileSystem (`lfs`)**
* **ANSI Escape Codes** (Colors and Text Formatting)
* **LuaStatic / Luamake** (Compilation and Binary Bundling)

---

## 2. Supported Local HTTP Server Features

**moonhttp** implements the essential features required for a *localhost* development environment:

* **Flexible Network Binding:** Supports listening on loopback interfaces (`127.0.0.1`, `localhost`), local network IP resolution, and custom hosts.
* **Automatic Directory Resolution:** `301 Moved Permanently` redirection for folder routes lacking a trailing slash (e.g., `/about` -> `/about/`).
* **Index Page Handling:** Automatic lookup for `index.html`, `index.htm`, or `index.lwa` documents.
* **MIME Type Identification:** Automatic recognition of `.html`, `.htm`, `.lwa`, `.css`, `.js`, `.ico`, and `.png` formats, with a fallback to `text/plain`. * **Development Cache Control:** Automatically sends `Cache-Control: no-cache` headers to prevent the browser from caching stale file versions during editing.
* **Method Security:** Strictly restricts requests to `GET` and `HEAD` methods, blocking attempts to modify files via `POST`, `PUT`, or `DELETE` (returning `405 Method Not Allowed`).
* **Immediate Port Release:** Uses the `SO_REUSEADDR` configuration to prevent the operating system from locking the port when the application is terminated via `CTRL+C`.
* **Optional File Listing:** Directory listing is disabled by default (returning `404 Not Found` for security reasons) but can be enabled on demand.

---

## 3. File Inspector and Web App Support

### Automatic Asset Inspection (Front-line)
When serving any HTML or `.lwa` document, **moonhttp** analyzes the code in real-time and inspects `<link>`, `<script>`, `<img>`, and `<a href>` tags. If a referenced file does not exist in the local folder, the server issues a **visual alert in the terminal** notifying you of the missing resource.

### Support for JS Frameworks and Web Applications

* **Supported Projects:** Static HTML5/CSS3/JS sites, landing pages, local templates, applications built with **Vanilla JS**, and `.lwa` files (treated as standard HTML).
* **JS Framework Builds (React, Vue, Svelte, Angular):** **moonhttp** seamlessly serves the static export folders generated by these tools (such as `dist/` or `build/`) after the framework's build command has been executed. * **Limitations (What it does NOT support):**
* It does not replace the *DevServer* with *Hot Module Replacement* (HMR) used during active development of JS frameworks (Vite, Webpack, Next.js). 
* It does not execute dynamic server-side code (Node.js, PHP, Python, etc.) or databases.

## 5. Complete CLI Command Guide

The base syntax for executing the binary is:

```bash
moonhttp [flags]
```

### Parameters and Arguments/Flags

| Description | Default Value |
| :--- | :--- |
|**-h:<host>**  | Sets the network interface/host to listen on (default: 127.0.0.1)|
|**-p:<port>** | Sets the server network port (default: 7777, or 8888 for moon/moonip profiles)|
|**--dir-list** | * Enables directory listing if no index file exists.|
|**-help or --help**| Displays the application help with available commands.|
|**-manual or --manual**| Displays the link to manual.md on GitHub.|
|**-v, -version, or --version**| Displays the moonhttp version.|

```
Disabled (Returns 404)
Practical Usage Examples

1. Standard Execution (Most Basic) Starts the server in the current working directory (CWD),
using IP 127.0.0.1 and port 7777. Bash: ./moonhttp | Windows: moonhttp.exe
```

#### 2. Using the 'localhost' Host Shortcut

> Sets the host to 127.0.0.1 on port 7777
```bash
./moonhttp -h:localhost
```

#### 3. Changing Only the Port
> Starts the server on custom port 5677 while keeping IP 127.0.0.1.
```bash
./moonhttp -p:5677
```

#### 4. Using the 'moon' Profile
> Uses the pre-configured 'moon' alias, which starts the server on IP 127.0.0.1 using port 8888.

```bash
./moonhttp -h:moon
```

#### 5. Sharing on the Local Network with 'moonip'
> Automatically identifies the machine's local network IP (e.g., 192.168.1.15) on port 8888, allowing other devices on the same Wi-Fi/Ethernet network to access the site.

```bash
./moonhttp -h:moonip
```

#### 6. Setting a Custom Host and Port
> Starts the server on a specific machine IP and a port of your choice.

```bash
./moonhttp -h:192.168.0.50 -p:3000
```

#### 7. Enabling Directory Listing
> Allows browsing the file structure in the browser if the folder does not contain an index.html file.

```bash
./moonhttp --dir-list
```

#### 8. Advanced Command (Local Network + Custom Port + Directory Listing)

Starts the server on the machine's local IP, using a manually defined port and with directory listing enabled.

```bash
./moonhttp -h:moonip -p:9000 --dir-list
```
